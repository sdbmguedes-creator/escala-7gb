2) DECISÕES TÉCNICAS (NÃO REVERTER)
═══════════════════════════════════════════════════════════════════════════════

- Matrículas como TEXT: contêm hífen (ex: 798041-8). NUNCA converter para bigint.

- elenco: PK composta (competencia, militar_id). Sem coluna 'id' (removida).

- marcas / comments / aco_oficiais: PK é 'id' (bigint auto-increment), mas
  a business key é UNIQUE:
    marcas:        UNIQUE(competencia, grupo, militar_id, dia)
    comments:      UNIQUE(competencia, chave)
    aco_oficiais:  UNIQUE(competencia, dia, turno)
  → upsert precisa de params={"on_conflict":"..."} explícito. Sem isso,
    PostgREST resolve pela PK e o merge-duplicates NÃO ativa (erro 23505).

- meta: PK = competencia. Upsert padrão funciona sem on_conflict.
- usuarios: PK = nome. Upsert padrão funciona (merge-duplicates implícito).

- logs_acesso: PK = id (bigint auto-increment). Inserção simples via POST
  (não usa upsert). Tem índice DESC na coluna 'ts' para busca rápida.

- Frontend camelCase nas chaves JSON. Backend snake_case interno.
  O pull DEVE retornar "acoOficiais" (camelCase), NÃO "aco_oficiais".
  Variáveis Python podem ser snake_case — só a chave JSON importa.

- PostgREST trunca em 1000 linhas/req. sb_select agora PAGINA automaticamente
  com offset quando limit=None ou limit>1000. NÃO remover essa paginação —
  com >1000 marcas o pull trunca silenciosamente (bug de 160 marcas invisíveis).

- Frontend aplicarRemoto:
    marks = remoto.marks;  ← SEM GUARDA, intencional (server é fonte)
    outros campos com `if (Object.keys(...).length)`  ← guard defensivo
  NÃO "consertar" marks para merge — design server-soberano é intencional.

3) FIXES CRÍTICOS E AUDITORIA DE SEGURANÇA (APLICADOS E VALIDADOS)
═══════════════════════════════════════════════════════════════════════════════

✅ FIX A — _push delta upsert (crítico, multi-dispositivo)
   Bug original: "DELETE-all + INSERT-all" apagava tudo em cada push.
   Correção: marcas_upsert/marcas_deletar + equivalentes p/ comments, elenco, aco.
   on_conflict explícito nos 4 upserts. Bump de versão sempre que aplicadas > 0.

✅ FIX B — _pull sempre completo (crítico)
   Removido {semMudanca: true} que retornava payload vazio.
   Sempre retorna: marcas, comments, elenco, acoOficiais, movimentos, meta.

✅ FIX C — sb_select com paginação (crítico)
   PostgREST limitava a 1000 linhas. Agora pagina com offset até esgotar.

✅ FIX D — poll não reaplica/loga quando versão não muda
   Guard no atualizarDoServidor: if (_ultimaRemota > 0 && r.versao === versaoAntes) return;

✅ FIX E — resolver_token valida expira_em
   Antes só checava ativo=true. Agora checa expira_em < agora (fail-safe).
   Sessões > 30 dias são rejeitadas.

✅ FIX F — login rate limit com janela de 15 min
   Nova chave LOGIN_ULTIMA_TENTATIVA. Se última tentativa > 15min atrás, 
   contador zera. Acabou o bloqueio permanente (DoS) do login.

✅ FIX G — _criar_usuario e _redefinir_pin invalidam sessões antigas
   Substituído DELETE+INSERT por upsert. Sessões antigas em 'sessoes' são
   apagadas em ambas operações. Se Admin mudar PIN, o usuário cai no próximo pull.

✅ FIX H — op 'oficial' restrito a Admin/Mestre no backend
   Antes só o frontend bloqueava. Agora o _push recusa 'oficial' se
   perfil não for Admin/Mestre (fecha bypass de SB via console).

✅ FIX I — auto-logout no frontend ao receber 401
   Interceptor global no window.fetch. Se 401 (exceto /login), limpa 
   localStorage e recarrega. Sessões revogadas/expiradas caem na hora.

✅ FIX J — op 'elenco' restrito a Admin/Mestre (fase 2)
   Frontend esconde a aba "Militares" para perfis SB. Backend recusa
   ops 'elenco' se perfil não for Admin/Mestre.

✅ FIX K — op 'mov' restrito e autor forçado (fase 2)
   Autor do movimento é forçado para u["nome"] (ignora payload).
   Op restrito a Admin/Mestre (evita spam no log de auditoria).

✅ FIX L — Exibe nome do usuário logado no cabeçalho
   Span #lblNomeUsuario adicionada ao lado do seletor de perfil.

✅ FIX M — Limite de 1 sessão por usuário
   No _login, antes de gerar o token novo, as sessões antigas daquele
   usuário são apagadas (sb_delete). Se logar no PC e depois no celular,
   o PC cai no próximo pull (401).

✅ FIX N — Correção da aba "Acessos" (Sessões e Último Acesso)
   _listar_usuarios agora busca as sessões ativas reais e faz um parse 
   do 'logs_acesso' (limit=500) para exibir o último login. Não é mais
   chumbado em 0.

✅ FIX O — Evita tela piscando na Auditoria
   atualizarDoServidor verifica se o botão 'AUDITORIA' está ativo. Se 
   estiver, não chama desenhar() para não expulsar o usuário da tela.

✅ FEATURE — Tela de Auditoria (Logs de Acesso)
   - Tabela 'logs_acesso' criada no Supabase (id, nome, perfil, acao, ts, detalhes).
   - Helper registrar_log() silencioso no backend.
   - Endpoint /logs (restrito a Admin/Mestre).
   - Triggers de gravação: _login, _logout, _redefinir_pin, _criar_usuario,
     _revogar_usuario e _encerrar_sessoes.
   - Interface no frontend (botão "AUDITORIA" via setInterval injetado,
     exibindo tabela com cores por tipo de ação: Login=verde, Revogado=vermelho).

✅ FEATURE — PWA (Aplicativo Instalável)
   - Criados 'manifest.json', 'sw.js' e ícones (192x192 e 512x512).
   - Registro do Service Worker no index_v14.html.
   - O app funciona em modo 'standalone' (tela cheia) e tem cache offline 
     do esqueleto da página.

✅ FIX P — Backend serve arquivos estáticos para o PWA
   - O do_GET no app.py intercepta chamadas para .json, .js e .png e 
     devolve o Content-Type correto, em vez de devolver o index_v14.html.
   - Sem isso, o Chrome bloqueava a instalação do PWA alegando MIME type 
     inválido ou erro de sintaxe no manifest.

✅ _redefinir_pin — VALIDADO empiricamente
   PK de usuarios é 'nome', então merge-duplicates resolve sem on_conflict.

✅ Endpoints corrigidos (DELETE com params em vez de body):
   - _logout, _revogar_usuario, _encerrar_sessoes

✅ FEATURE — Exportação CSV e Impressão PDF
   - Função exportarCSV() gera uma planilha em grade com todas as seções 
     (ACO, 1ªSB a 4ªSB, ADM, Visitantes) lendo o estado real do sistema.
   - CSS @media print configurado com zoom (0.60) e paisagem (landscape)
     para imprimir a escala inteira no papel sem cortar as colunas.

✅ FEATURE — Histórico de Movimentações
   - Nova aba "MOVIMENTAÇÕES" (Admin/Mestre) lendo o array D.movimentos.
   - Mudanças de seção (função trocarSecaoMilitar) agora enfileiram duas ops:
     op 'elenco' (para mudar no banco) e op 'mov' (para registrar no histórico).
   - Adicionada a coluna "Autor" no histórico para auditoria.

✅ FIX Q — Sincronização de Elenco (D.mes) no Frontend
   - O _pull agora envia o elenco. A função estadoDoServidor repassa e o
     aplicarRemoto atualiza o D.mes (seção, escala, afastamentos, etc).
   - Antes, o frontend só usava o localStorage para o elenco, o que fazia
     com que mudanças de seção feitas por um Mestre não aparecessem para os
     outros perfis (Admin/SB).

✅ FIX R — Controle nativo de abas por perfil (Menu UI)
   - Abas DIARIO, OPERACIONAL, MILITARES, AFASTAMENTOS, MOVIMENTAÇÕES e 
     AUDITORIA só são construídas no menu se o perfil for Admin ou Mestre.
   - Eliminado o setInterval de controle de menus. O desenhar() agora é a
     única autoridade sobre a barra de navegação.

✅ FASE 4 — Otimização de Performance e Resiliência Offline
   - Polling ativo reduzido de 5s para 2s (PULL_ATIVO_MS = 2000).
   - Polling ocioso reduzido para 30s (PULL_OCIOSO_TICKS = 15).
   - Novo Event Listener 'visibilitychange' no frontend: quando o usuário 
     volta para a aba do navegador, o sistema puxa os dados na hora, sem 
     precisar de F5.
   - Monitor de conexão (navigator.onLine): exibe aviso amarelo 
     "⚠️ OFFLINE (Salvando local)" no topo e verde "Sincronizando..." quando 
     a internet volta. A fila de operações pendentes é enviada automaticamente.
   - O tempo de bloqueio de interação caiu de 3s para 1s.

✅ FASE QA — Suíte de Testes Automatizados
   - Backend: Pytest configurado em 'api/tests/test_api.py'. Valida 
     bloqueio de PIN errado, push sem token e acesso indevido à auditoria.
     Para rodar: python -m pytest api/tests/ -v
   - Frontend: Cypress configurado em 'cypress/e2e/escala.cy.js'. Valida 
     tela de PIN, mensagem de erro e login com sucesso.
     Para rodar: npx cypress run --browser chrome
   - node_modules e pastas de vídeo do Cypress adicionados ao .gitignore.

✅ FASE CI/CD — GitHub Actions
   - Criado o arquivo '.github/workflows/ci.yml'. Ele roda o Pytest (API) 
     e o Cypress (Interface) automaticamente a cada push ou Pull Request.
   - Branch 'main' configurada com "Branch Protection Rule" no GitHub.
     O merge de Pull Requests só é liberado se os dois testes passarem.
   - Testado com sucesso: PR com teste quebrado foi bloqueado pelo GitHub.

7) LIÇÕES APRENDIDAS
═══════════════════════════════════════════════════════════════════════════════

- NUNCA confiar no frontend para validar regras de negócio (ex: permissões de 
  perfil). O usuário pode injetar payloads via console. O backend deve sempre
  validar (Cenário A: op elenco e mov restritos a Admin/Mestre).
- Não confiar em "deve ser cache" — investigar sempre.
- Múltiplos projetos Supabase = confusão. Confirmar current_database() antes.
- PostgREST trunca em 1000 sem aviso. Paginação obrigatória.
- on_conflict explícito quando PK ≠ business key.
- "Server é fonte das marcas" (marks = remoto.marks sem guard) é design, não bug.
- Backup antes de mudanças em produção. Sempre.
- Editar arquivos Python com VS Code, não com PowerShell Set-Content.
